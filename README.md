# Lexicona

Личный англо-русский словарь с тренировками. Свой словарь и свой прогресс у каждого
человека. Открывается в браузере на телефоне, планшете и компьютере. Аккаунты создаёт
владелец, открытой регистрации нет.

## Что внутри

- слова с несколькими переводами, транскрипцией, примером, заметкой и своими тегами;
- поиск и фильтр: несколько тегов означают «любой из выбранных»;
- подсказка перевода из локального словаря и, если его нет, из DeepL или DeepSeek;
- тренировки: выбор из шести, письменный ответ и сопоставление пар;
- направления EN → RU и RU → EN, своё число слов или все подходящие;
- после ошибки можно исправить ответ без второго штрафа;
- прогресс не ограничен 100% и зависит от выбранной сложности;
- занятия по расписанию повторений и свободная практика, которая расписание не меняет;
- незаконченное занятие можно продолжить;
- статистика первых ответов по дням;
- слово можно убрать из тренировок и вернуть, прогресс сохранится.

## Озвучка

В настройках для английского и русского отдельно выбираются источник и голос,
а также общая скорость и автоозвучка вопроса. По умолчанию звучат оба языка.
Снятый язык в словаре и на тренировке не произносится.
Кнопка «Проверить» в настройках по-прежнему произносит образец.

Серверные голоса — Kokoro на вашем компьютере, без внешнего сервиса озвучки.
В каталоге 28 английских голосов: 20 с американским произношением и 8 с британским,
женские и мужские. По умолчанию выбраны Heart для американского и Emma для британского.
Русский текст произносит голос браузера. Первая фраза после запуска ждёт загрузку модели.
Голос браузера зависит от устройства; сетевой голос может отправлять текст своему сервису,
это видно при выборе.

Kokoro работает в отдельном Python 3.13, потому что основной сервер использует Python 3.14.
Из корня проекта:

```sh
make kokoro-install
make voices
```

Вторая команда один раз скачивает около 354 МБ моделей в `backend/data/tts/kokoro`
при настройках по умолчанию. Образ Docker уже содержит это окружение Python.
Модели в контейнер ставятся отдельно, в каталог данных:

```sh
docker compose --profile lexicona exec app python -m lexicona.infrastructure.kokoro download
```

В настройках озвучки выберите серверный источник и английский голос. Сохранённый
голос прежнего каталога заменяется Heart или Emma того же акцента.

## Установка на телефон, планшет или компьютер

Откройте сайт по HTTPS и в настройках нажмите «Установка». На iPhone и iPad в Safari:
«Поделиться», затем «На экран Домой».

### Ubuntu: Chrome из Flatpak

Сначала проверьте меню приложений (Super → «Lexicona»): если ярлык уже работает
и имеет значок, ничего создавать не нужно. Если установка из Chrome не создаёт
ярлык, проверьте пакет через `flatpak list --app`. Только для `com.google.Chrome`
при необходимости можно разрешить запись в два пользовательских каталога:

```sh
flatpak override --user \
  --filesystem=xdg-data/applications:create \
  --filesystem=xdg-data/icons:create com.google.Chrome
```

Это расширяет доступ Chrome к вашим ярлыкам и значкам. Сохраните работу, закройте
окна Chrome и установленных через него приложений обычным способом, завершите
Chrome через его меню (включая фоновую работу, если она включена), затем откройте
снова. Установите Lexicona в нужном профиле, только если она ещё не установлена.
Не завершайте все процессы Chrome принудительно и не переустанавливайте приложение
ради значка.

**Если значок пустой или ярлыков два**, сначала посмотрите существующие записи.
Следующая команда только читает файлы; она показывает и другие приложения Chrome:

```sh
for dir in \
  "${XDG_DATA_HOME:-$HOME/.local/share}/applications" \
  "$HOME/.local/share/flatpak/exports/share/applications" \
  /var/lib/flatpak/exports/share/applications
do
  if [ -d "$dir" ]; then
    find "$dir" -maxdepth 1 \( -type f -o -type l \) -iname '*chrome*.desktop' \
      -exec grep -H -E '^(Name(\[[^]]+\])?|Exec|Icon|StartupWMClass|X-Flatpak)=' {} +
  fi
done
```

Сопоставьте `Name=Lexicona`, `--app-id` и `--profile-directory` в `Exec` с приложением
в нужном профиле Chrome. Если указан `--user-data-dir`, он тоже должен совпадать.
Одинаковое название ещё не означает дубликат: другой профиль, приложение или
установка Chrome могут требовать отдельный ярлык. Не выбирайте самый свежий PNG
и не считайте профиль `Default` единственно возможным.

Для **одного точно выбранного существующего пользовательского `.desktop`**:

1. В файловом менеджере включите скрытые файлы (Ctrl+H). Скопируйте выбранный файл
   в `~/.local/state/lexicona/launcher-backups/`, создав каталог при необходимости.
   Дайте копии уникальное имя с датой, чтобы не затереть предыдущую.
2. Откройте оригинал в текстовом редакторе. В секции `[Desktop Entry]` исправьте
   только `Icon=`. Абсолютный путь должен вести к существующему изображению,
   доступному **на хосте**, а не только внутри песочницы. Имя значка темы пишется
   без пути и расширения: например, `chrome-APP_ID-PROFILE`, но только если
   соответствующий PNG действительно найден в пользовательском
   `icons/hicolor/.../apps/` и относится к этому приложению и профилю.
   `APP_ID` и `PROFILE` здесь — обозначения, не готовые значения для копирования.
   Не меняйте `Exec`, имя файла и профиль; не создавайте второй `.desktop`.
3. Если второй пользовательский файл подтверждён как устаревший дубликат той же
   установки, app ID и профиля, сначала проверьте запуск оставляемого ярлыка.
   Затем переместите **только этот конкретный дубликат** в каталог резервных копий
   под уникальным именем. Не удаляйте файлы по маске. Для отмены верните файл
   на исходное место; резервная копия также позволяет отменить правку `Icon=`.

Не редактируйте и не перемещайте экспортируемые Flatpak файлы или символические
ссылки в `flatpak/exports`: ими управляет Flatpak. Префикс пакета в имени сам
по себе не доказывает, что запись лишняя. Если не удалось однозначно определить
файл или найти изображение, остановитесь на диагностике, а не создавайте новый ярлык.
После изменения заново откройте меню приложений; если оболочка хранит старую
запись, сохраните работу и выйдите из сеанса Ubuntu, затем войдите снова.
Закреплённый старый ярлык при необходимости открепите и закрепите оставшийся.

Основания: [разрешения Flatpak](https://docs.flatpak.org/en/latest/sandbox-permissions.html#filesystem-access),
[экспорт desktop-файлов](https://docs.flatpak.org/en/latest/conventions.html#desktop-files),
[ключ Icon](https://specifications.freedesktop.org/desktop-entry-spec/latest/recognized-keys.html)
и [поиск значков темы](https://specifications.freedesktop.org/icon-theme-spec/latest/#icon_lookup).

### Как удалить ярлык

Удаление ярлыка не удаляет слова и прогресс: они хранятся на сервере. Сначала
удалите установленное приложение в самом Chrome: откройте `chrome://apps`, нажмите
правой кнопкой на Lexicona и выберите «Удалить с Chrome». Chrome сам убирает
созданные им записи. Затем закройте и снова откройте меню приложений.

Если ярлык в меню остался, уберите **только один проверенный пользовательский
`.desktop`**:

1. Найдите файл командой `find` выше и сопоставьте `Name=Lexicona`, `--app-id`
   и `--profile-directory` с приложением в нужном профиле.
2. Скопируйте файл в `~/.local/state/lexicona/launcher-backups/` с уникальным
   именем и датой.
3. Переместите оригинал в тот же каталог резервных копий. Не удаляйте файлы
   по маске и не трогайте `flatpak/exports`.
4. Если ярлык закреплён, открепите его в меню или на панели.
5. Значок в пользовательском `icons/hicolor/.../apps/` можно оставить: он ничего
   не запускает. Удаляйте его, только если точно знаете, что он относится
   к этому приложению и профилю.

Если Chrome создаст ярлык заново при следующем запуске, это ожидаемо. Для отмены
верните `.desktop` на исходное место и заново откройте меню приложений.

## Как запустить у себя

Нужны [uv](https://docs.astral.sh/uv/) и Node.js 22+.

```sh
cd backend
uv sync
uv run alembic upgrade head
uv run lexicona-admin create-user me --admin
uv run uvicorn lexicona.main:create_app --factory --reload
```

Интерфейс в другом терминале:

```sh
cd frontend
npm install
npm run dev
```

Сайт разработки: http://localhost:5173. База лежит в `backend/data/lexicona.db`.
Словарь-подсказка собирается один раз командой `make dictionary`.

Ключи DeepL и OpenRouter необязательны. Без них работают локальный словарь и ручной
ввод. Имена переменных — в `.env.example`. Запросы к OpenRouter оплачиваются вашим ключом.

Проверка проекта: `make check`.

## Сервер

Один адрес на всех, аккаунт у каждого свой. База — файл `backend/data/lexicona.db` внутри проекта. Каталог `backend/data/` в git не входит, `git pull` его не затирает. Копия всего каталога проекта переносит базу на другой сервер. В `.env` укажите `LEXICONA_UID` и `LEXICONA_GID` как `id -u` и `id -g`, чтобы контейнер мог писать в эту папку.

Сайт открывается на порту `8443`: `https://<домен>:8443`. Caddy внутри контейнера слушает 443. Другой порт пишется в `.env`. Этот файл git не хранит, поэтому `git pull` его не затирает и `compose.yaml` после обновления менять не нужно.

```sh
LEXICONA_HTTPS_PORT=443
```

Без этой строки порт остаётся `8443`. После смены один раз выполните `docker compose --profile lexicona up -d` и откройте порт в файрволе. Следующие обновления репозитория порт не трогают.

В DNS одна A-запись: имя из `LEXICONA_DOMAIN` указывает на IP сервера.

```sh
LEXICONA_DOMAIN=lexicona.example.com
LEXICONA_TLS_DIR=/path/to/cert
LEXICONA_TLS_CERT=/path/to/cert/fullchain.pem
LEXICONA_TLS_KEY=/path/to/cert/privkey.pem
```

Это файлы Let's Encrypt. Имя в сертификате совпадает с доменом, оба пути лежат внутри `LEXICONA_TLS_DIR`. После замены файлов: `docker compose --profile lexicona restart caddy`.

Перед первым запуском создайте каталог данных от своего пользователя. Docker создаёт отсутствующий bind-mount от `root`, и контейнер с `LEXICONA_UID` не сможет писать в него:

```sh
mkdir -p backend/data
ls -ld backend/data
```

Владелец каталога должен совпадать с `LEXICONA_UID`/`LEXICONA_GID`. Если каталог уже создан от `root`, исправьте владельца от своего пользователя (`sudo chown "$(id -u):$(id -g)" backend/data`).

```sh
docker compose --profile lexicona up -d --build
docker compose run --rm lexicona-admin create-user me --admin
```

Сайт в профиле `lexicona`: обычные `up`, `stop` и `down` его не запускают и не останавливают. Остановка: `docker compose --profile lexicona stop`. Команда `lexicona-admin` спрашивает пароль и лежит в своём профиле `lexicona-admin`, поэтому запуск сайта её не трогает.
