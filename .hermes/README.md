# Project-local Hermes skills

Эта папка содержит переносимые очищенные процедуры разработки Lexicona. Она входит в Git, но не в runtime веб-приложения. AGENTS.md остаётся самодостаточной точкой входа.

## На новой машине
После clone открыть корень проекта установленным Hermes. Проверить и один раз доверить именно этот checkout:

    hermes skills trust .

В новой сессии Hermes найдёт шесть project skills: lexicona-workflow, lexicona-architect, lexicona-python, lexicona-frontend, lexicona-linux, lexicona-review. Уже открытая сессия может сохранять прежний индекс; это не причина переписывать global config или создавать дубли skills. На другом checkout/worktree доверие может требоваться отдельно.

Workflow координирует ограниченные задания через встроенный delegate_task: максимум три дочерних агента, без автономных фоновых служб и других coding CLI. Skills сами не запускают процессы, не являются sandbox и не создают профили.

## Что сюда не переносится
Полный HERMES_HOME, credentials, .env/auth tokens, память, transcripts, локальные отчёты, ТЗ, макеты, временные task state и личные данные не включаются в Git. Локальная .lexicona/ опциональна; отсутствие её после clone не мешает читать эти правила.

MCP connections живут в активном профиле Hermes, а не автоматически в произвольном .hermes/mcp.json. Для Lexicona нет обязательного MCP/runtime-сервиса: native file/terminal/browser tools и обычные project tests достаточны, Context7 опционально помогает с публичной документацией. Подключения на новой машине настраиваются поддержанными инструментами отдельно, с минимальными правами и без копирования секретов. Просто наличие manifest не означает проверенную связь.

## Проверка переносимости
Отсутствуют абсолютные пути машины/пароли/токены и обязательные ссылки на приватные файлы. Все шесть SKILL.md имеют name/description, платформенные ограничения и конкретный порядок/verification. Нативное обнаружение проверяется отдельным свежим процессом Hermes после trust; это не обещание регистрации произвольных файлов как агентов.
